# Release Notes Instructions

- Describe user-visible impact and outcome, not implementation details. Keep the language factual.
- If the heading links to a PR, do not repeat that PR link in the body.
- Link issues in the body where they exist, including issues that give a bug's context.
- If the issue reporter also authored the fix (check the commit author), write `Thanks to [@handle](https://github.com/handle) for the fix.`
- Otherwise, credit a known reporter with `Thanks to [@handle](https://github.com/handle) for reporting.`
- Put the attribution in the same paragraph as the issue it relates to.
